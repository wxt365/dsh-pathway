## 3. assistant / turn / step：逐回复树应使用的事实

### 3.1 持久事件形状

事件外层包含 `type / seq / time / data`；surface 事件还携带 `surfaceOp`。不要把实时流的 frame 当持久 SessionEvent。

| 事件 | data 形状及语义 | 一手代码 |
| --- | --- | --- |
| `turn/start` | `{turn:number}`；在领取第一步输入之前打开 turn | [agent-loop:937–945](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L937-L945>) |
| `step/start`、`step/end` | `{turn,step}`；被拒绝或空首批输入可以不产生 step | [agent-loop:955–973](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L955-L973>)、[994–997](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L994-L997>) |
| `assistant/message` | `{turn,step,message,stream,usage?,interrupted?:true}` | [agent-loop:1148–1162](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L1148-L1162>) |
| `assistant/attempt` | `{turn,step,stream}`；失败、重试或没有可展示内容的中断尝试，不添加模型历史 | [agent-loop:1093–1146](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L1093-L1146>) |
| `turn/end` | `{turn,reason:{kind,...}}`，不是字符串 `reason` | [agent-loop:1010–1032](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L1010-L1032>) |

`message` 是 `{id,role:"assistant",content:[...],source:{kind:"model",provider,model,...}}`。文本在 **`data.message.content.filter(b=>b.type==='text').map(b=>b.text)`**；不是 `data.text`、不是 `data.content`，也不是 `data.message.text`。`reasoning` 与 `tool-call` block 不能混成最终回答文本。构造证据：[LLM message 工厂:37–41、70–78](<../.harness-reference-current/dsh-llm/lib/index.js#L37-L78>)。正式 TextBlock 声明为 `{type:'text',text:string}`：[生成的协议类型:3123](<../.harness-reference-current/dsh-api-session-controller/lib/typert.host.js#L3123>)。

`turn/end.reason.kind` 包含 `completed / aborted / blocked / error / max-tokens / interrupted / forked`；`aborted` 的内层 `reason` 是取消原因，`error` 带 `error`。类型证据：[TurnEndReasonMap:3183](<../.harness-reference-current/dsh-api-session-controller/lib/typert.host.js#L3183>)。冷读可能追加 `interrupted` 合成闭合事件，不能把它们冒充实际工具成功完成：[cold-read:24–27、47–53](<../.harness-reference-current/dsh-session-query/lib/index.js#L24-L53>)。

### 3.2 分组建议（供主代理适配，不在本任务改代码）

1. 基本边界键用 `(sessionId, turn, step)`，持久回复身份用 `message.id` 或事件 `seq`。**step 在新 turn 重置**，不应单独作为全局键：[agent-loop:1037–1040](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L1037-L1040>)。
2. 同一 turn 可有多个 assistant/message：含工具请求的回复 → 工具结果 → 下一 step 的最终文字。不能每 turn 只保留最后一条，也不能把每条回复都宣称是最终答案。可见文本和工具请求应按同一个 assistant 事件关联，tool-call block 的 `id` 对应工具 `callId`。
3. 中断且有可保留内容时会产生 `assistant/message` 并标 `interrupted:true`；失败重试通常是 `assistant/attempt`。空内容 assistant/message 也可能存在，不能无条件显示为空白最终回复：[agent-loop:1096–1117](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L1096-L1117>)、[session 注释:825–828](<../.harness-reference-current/dsh-session/lib/types/index.js#L825-L828>)。
4. `user/message` 的 data **直接是 UserMessage**，并不是 `{message:...}`，也不保证自身有 turn/step；需依据边界/序列定位，不能套 assistant 解包路径。证据：[SessionEventMap:2807](<../.harness-reference-current/dsh-api-session-controller/lib/typert.host.js#L2807>)。
5. raw log 的 surface replacement 与历史删除/压缩不是同一个概念。若产品展示“执行历史”，可以保留历史事件但应标明这是原始日志；若宣称“当前模型可见对话”，需要遵循 surface/projection，不能简单拼接全部 assistant/message。证据：[session README:127](<../.harness-reference-current/dsh-session/README.zh.md#L127>)。
6. `stream` 是紧凑带时间 provider 记录，不应当二次拼到已经组装的 `message.content` 后面。实时 `agent/assistant-stream` 的 `start/chunk/end` frame 是进程内通知，`start` 带 turn/step，后续 frame 以 attemptId/revision/index 关联，`end.outcome` 指向 committed seq 或 abandoned；不是 `turn/start/end`。证据：[agent-loop:385–450](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L385-L450>)。

## 4. 工具 call/result 与 PTC

### 普通工具

- `tool/call.data = {turn,step,callId,name,arguments}`，这里 `arguments` 是 JSON **字符串**：[agent-loop:681–688](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L681-L688>)。
- `tool/result.data = {turn,step,message,error?,meta?}`，没有保证顶层 `callId`；应读 `message.toolCallId` 或 `message.source.callId`。`message = {id,role:'tool',source:{kind:'tool',callId},toolCallId,content,isError}`：[LLM:101–111](<../.harness-reference-current/dsh-llm/lib/index.js#L101-L111>)。
- `tool/result` 外层为 `surfaceOp:'append'` 且 `sourceEventSeqs:[callSeq]`，可以作为可靠 call 关联事实：[agent-loop:697–706](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L697-L706>)。恢复或替换事件也应关注自己的 surface 语义，不能仅按出现顺序猜测覆盖。
- 取消后尚未派发的调用可能仍有合成 `tool/call` + 错误结果，错误码 `ABORTED_BEFORE_DISPATCH`，故记录了 call 不等于外部操作已运行：[agent-loop:662–678](<../.harness-reference-current/dsh-agent-loop/lib/index.js#L662-L678>)。恢复还有 `TOOL_NOT_STARTED`、`TOOL_OUTCOME_UNKNOWN`，不可把后者断言为失败/无副作用：[session README:171](<../.harness-reference-current/dsh-session/README.zh.md#L171>)。

### PTC 内嵌派发

- `tool/ptc-dispatch-start.data = {rootCallId,parentCallId,subCallId,name,arguments}`。
- `tool/ptc-dispatch.data` 再加 `{isError,content,error?,meta?}`。
- **PTC data 不自带 turn/step**，arguments 是归一化后的值（可为对象），不是普通工具 call 的字符串保证。按 `subCallId` 配对，并按 `parentCallId` 建嵌套边，`rootCallId` 保留根关联；不把脚本内部任意 I/O 推断为工具。
- 一手记录代码：[tools:1362–1375](<../.harness-reference-current/dsh-tools/lib/index.js#L1362-L1375>)、[1400–1429](<../.harness-reference-current/dsh-tools/lib/index.js#L1400-L1429>)；声明：[PTC 类型:2655–2659](<../.harness-reference-current/dsh-api-session-controller/lib/typert.host.js#L2655-L2659>)。官方 UI 也按 parent/sub ID 建边并防环：[trajectory:2343–2395](<../.harness-reference-current/dsh-client-ui-trajectory/lib/client.js#L2343-L2395>)。

## 5. Host 接口兼容性

### 路由：继续兼容

本项目 [Host:33–60](<../src/host.js#L33-L60>) 使用 `ctx.connection.fetch.register({path,methods:['GET'],requestBody:'buffered',fetch})`，新版接口完全存在：[connection:731–735](<../.harness-reference-current/dsh-client-connection/lib/index.js#L731-L735>)。

- 路由必须位于 `/api/<endpoint>`，方法列表非空且无重复：[connection:973–976](<../.harness-reference-current/dsh-client-connection/lib/index.js#L973-L976>)。
- 精确路径/方法匹配，owner principal 才能访问；connection 负责 Host/Origin 与认证准入，插件不应另建无认证旁路：[connection:736–747](<../.harness-reference-current/dsh-client-connection/lib/index.js#L736-L747>)、[820–836](<../.harness-reference-current/dsh-client-connection/lib/index.js#L820-L836>)。
- 自动使用调用方 owner.effect 注销路由：[connection:840–853](<../.harness-reference-current/dsh-client-connection/lib/index.js#L840-L853>)。
- 仅注册 GET 时，其他方法不会进入插件自己的 `onlyGet()`，通常由共享 carrier 返回 404；不应声称宿主 POST 一定能得到插件的 405。

### 会话读取与列表

- `await ctx.sessionQuery.readSession(id)` 返回 `{session:header,inheritedEventCount,events}`，克隆完整事件、replay validate、不会使冷会话 live：[sessionQuery:1075–1088](<../.harness-reference-current/dsh-session-query/lib/index.js#L1075-L1088>)。本项目 [Host:70–79](<../src/host.js#L70-L79>) 解包路径匹配。
- `SESSION_QUERY_SESSION_NOT_FOUND` 仍是找不到会话的错误码：[sessionQuery:313](<../.harness-reference-current/dsh-session-query/lib/index.js#L313>)。本项目 [Host:83–85](<../src/host.js#L83-L85>) 映射匹配。
- 完整逻辑语料列表方法叫 **`sessionQuery.listSessions(signal?)`**，不是 `sessionQuery.list()`；返回 `[{header,live,persisted,formatStatus?}]`，live 优先、最新在前：[sessionQuery:95–117](<../.harness-reference-current/dsh-session-query/lib/index.js#L95-L117>)、[1072–1073](<../.harness-reference-current/dsh-session-query/lib/index.js#L1072-L1073>)。
- 本项目当前列表调用的是 **`ctx.sessions.list()`** 并明确标 `scope:'live-only'`：[Host:43–49](<../src/host.js#L43-L49>)。这个方法继续存在（新版 corpus 自身也使用），但它不是完整已持久化会话列表。不能把“trace 支持冷读”和“下拉列表能发现所有冷会话”混为一谈。
- `readSession(id)` 当前没有 signal 参数；插件在读取前后检查 abort 不能中断底层完整冷读，当前 20,000 条/8MiB 限制也是读完后的限制，不是流式读取。证据：[Host:8、67–74](<../src/host.js#L67-L74>)、[sessionQuery:1081–1088](<../.harness-reference-current/dsh-session-query/lib/index.js#L1081-L1088>)。

## 7. 对本项目的最终判断与后续最小工作

1. **版本：本机已升级 rc.5，不能再拿 rc.3 参考声明当前运行时。**
2. **必须先解决 manifest 精确引擎约束，才能在正常准入下宣称支持 rc.5。** 这是后续代码/打包代理负责的修改；本次没有修改约束或添加风险豁免。
3. **不需要为 rc.5 捏造另一套 Host/client 路由、factory 或 slot 协议。** 本项目已用的接口形状仍匹配；本次关键文件比较还证明这些形状早在 rc.3 就已存在。
