# 结论与证据协议（schemaVersion 1）

## 目的与边界

Harness 原始工具事件可以证明一次工具调用及其返回，但不能自动证明模型的某句话使用了其中哪些内容。本协议记录**显式声明的引用**，不声称还原私有思维或证明因果。

完整示例见 [演示 trace](<../examples/demo.trace.json>)。程序校验入口为 [核心模块](<../src/core.js>) 中的 validateTrace/importTrace/exportTrace。

## 按回复绑定（0.2 新增，可选 replies）

schemaVersion 仍为 1，旧 trace 缺少 replies 会补空数组并显示 legacy 计划。要把结论绑定到具体回复，新增：

```json
{
  "replies": [
    {
      "id": "reply-1",
      "kind": "assistant",
      "status": "recorded",
      "text": "Q3 收入高于 Q2。",
      "turn": 1,
      "step": 2,
      "time": null,
      "nodeIds": ["session-1:call-1"],
      "claimIds": ["C1"]
    }
  ]
}
```

这段是完整 trace 的附加字段，不是独立可导入文件。nodeIds 是执行归属，不证明证据支持；claimIds 才控制这条回复在显式证据模式中的结论分支。不要把整个会话所有节点/结论复制到每条回复。

宿主投影只收集 assistant/message 的 text blocks；同轮回复按提交顺序关联先前工具，tool-call-only 与 assistant/attempt 不冒充正文。中断文本保留 interrupted 标记。未记录结束的调用可作为当时已开始的执行出现，但必须保留未记录返回状态；之后才返回的完整工具结果不倒挂到此前已提交回复。跨轮执行不自动继承。展示的是原始执行历史，不是 surface replacement 后的当前模型可见对话。

## S1 截面字段与裁剪导出

新宿主投影包含 trace.orderBasis、工具callSeq/resultSeq/resultState/activityState，以及正文cutSeq/orderBasis/nodeViews。nodeViews为按nodeIds同序的严格白名单投影，校验器根据canonical工具记录重新计算并逐字段比较；不要手工复制全局工具output填入早回复。缺少可靠seq时整份使用input-order，不声称宿主提交事实。

工具调用在回复前、返回在回复后时，早回复view保留开始记录，但output/end为空、sourceIds为空、resultState=missing-result、activityState=unknown。全局时间线仍可查看后来生命周期；计划详情不得回读全局未来结果。

“导出结构”仅保留白名单元数据；“导出选中内容”按所选reply/claim裁剪并确认。两者输出可独立导入的schema1记录，为避免把被裁剪全局节点误当原始生命周期，省略新状态/seq与reply.nodeViews全套，保留exportScope及必要截面不可用标识。此包不是原始宿主日志，不可据此恢复省略内容或证明完整性。

## 登记真实结论

1. 从宿主导出 trace，或用事件转换脚本生成。
2. 按当时返回快照添加 evidence。使用已有 sourceId/nodeId，填 locator 和原文 excerpt；不要在当前文件重新选一段替代历史快照。
3. 添加 claims，显式列出 evidenceIds 与 limitations。
4. 导入查看器，检查悬空引用并点击结论反查来源。

导入一律标记为 IMPORT。即使 JSON 中自称 harness 或已验证，也不能据此获得宿主事实/语义验证身份。MVP 没有数字签名和防篡改审计；JSON 可以被编辑。

## 定位约定

- 文本：L12–L20；绑定来源快照，而不是当前磁盘行号。
- JSON：`/data/orders/7/refund_amount`，建议补业务主键。数组位置只对该响应快照有效。
- Excel：工作表 + A1 范围；PDF：页码 + 原文片段。
- 计算结果：nodeId + 输出字段/片段。执行脚本见 node.input，结果见 node.output。

MVP locator 是可读字符串，展示和跳转到来源节点，不自动验证行片段、JSON Pointer 语义、单元格存在性或计算正确性。未来可添加结构化 locator 与独立核验报告，不能提前把 UI 定位误称为验证通过。

## 校验与安全

- schemaVersion、必需数组、节点状态、时间、重复 ID 与主要类型受校验。
- 悬空引用保留并报警，不能通过猜测补造。
- 每条结论与证据的 verification 都归一为 unverified。
- 全部导入/导出先脱敏，限制 8 MiB、对象深度和字符串长度。
- UI 只用文本渲染片段，不执行 HTML、不自动请求来源 URL。
