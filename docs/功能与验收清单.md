## 3. 0.5.0现场验收步骤

1. 用户方便时完整退出再打开应用（Host/core/native工具已变；不能仅刷新）。不要由Agent中断用户任务。
2. 刷新执行链路数据，在页签上方确认“查看范围”和唯一回复选择器可见。
3. 当前回复范围选择Turn45 Step6：结论页应有2条结论、来源页有3份文档，显式证据图有3条唯一证据、4次引用；两个证据2均显示共享·2条结论。
4. 选择无登记的较新回复：结论页不残留Turn45的两条；切回快照范围可看到已加载的其他结论。
5. 选一次工具结果尚未返回的早先回复（若记录存在），时间线详情不应出现后续返回和来源。
6. 记录截图/结果后才将对应现场项改为通过；不因按钮出现就关闭全部验收。

## 4. 窗口外旧来源专项

严格成功条件是被引用read的call/result seq早于该次快照firstSeq，且原生accepted绑定新正文、GUI补取历史来源并显示摘录。仅跨turn不等于跨窗口。

- 不重新读取原来源，否则测到的是新记录。
- 先从已保存结果获取旧nodeId/sourceId/精确摘录，再执行原生登记，target next-text-message；无可用旧来源则明确不可完成，不编造ID或摘录。
- 旧来源即使不在list最新子集中，只要真实ID及摘录已在可用上下文中，仍可显式登记；登记校验决定可用性。
- GUI记录信息核对firstSeq和旧来源seq，保存证据后才关闭专项。
- 如旧来源仍在窗口内，本次仅能算跨轮复用成功，不能通过大量填充会话人为撑窗或宣称窗口外恢复通过。

## 5. 收尾标准

单会话MVP开发完成≠完整路线完成。先关闭第3节和第4节现场项，再在“历史按需浏览”和“多Agent证据”之间明确下一阶段范围。开发状态变化须同步本表和验证记录。
