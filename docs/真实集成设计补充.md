## 1. 本轮决策摘要

1. 保留紧凑横向图：结果在左，输入在右；执行关系与证据关系不同色/线型。
2. S1 只读、手动刷新快照；先保证真实执行可查，不引入实时流竞态。
3. 不用模型文本语气、是否最后一条或工具名猜测“最终回答”“仍在运行”“子 Agent 已关联”。缺记录就未知。
4. 每条正文消息有自己的提交截面；跨轮证据必须显式引用，不自动把整个历史挂上去。
5. 子 Agent 第一阶段采用折叠委派节点与子会话跳转，不铺开全部子会话。
6. 证据登记作为 S2 独立能力；没有登记不阻止正常回答，也不生成假依据。
7. S1 的安全出口是默认结构导出、按选择范围确认后导出内容。现有全量正文导出不能作为新默认。
8. 所有安装/启用、profile 修改均需用户确认；不启动替代 GUI、不绕过宿主认证。

## 3. 回复归属与提交截面

### 3.1 身份和顺序

- 事件身份：`sessionId + seq`；工具身份：`sessionId + callId`；正文身份优先 `sessionId + message.id`。
- seq 才是同会话提交顺序；时间仅用于展示/耗时。重复 seq 内容冲突应报警，不能静默选一个。没有可靠 seq 的导入数据标记顺序依据为 input-order，不声称宿主提交事实。
- 读取到的日志是一个快照；回复的 cutSeq 为该条 assistant/message 提交位置。重复刷新不能让该回复获得后来发生的结果。
- 不保留或展示 reasoning blocks；tool-call-only 和 assistant/attempt 不作为正文回复。

### 3.2 归属规则表

| 情况 | 显示/关联规则 | 不允许的行为 |
|---|---|---|
| 同 turn、调用和结果都早于 cutSeq | 作为该回复的“此前执行” | 自动认定为回复依据 |
| 同 turn、调用早于 cutSeq，结果尚无或晚于 cutSeq | 可列为“当时已开始、当时无返回”；不得附后来结果；详情可跳转看后续生命周期 | 在早先回复树里显示未来返回，或随刷新删除当时已开始事实 |
| 调用晚于 cutSeq | 留到后续回复/未绑定执行 | 倒挂到这条回复 |
| 同轮多条正文 | 各自 cutSeq；可共享此前记录，以“重复展示同一执行”标识 | 重复计算成多次实际调用 |
| 跨 turn 复用数据 | 显式证据引用先前来源；执行视图不自动继承整轮 | 把所有历史工具附在当前轮下 |
| 缺少 turn/父关系 | 未归属节点，说明缺少字段 | 使用当前选中回复或时间接近猜测 |
| 中断时提交的正文 | interrupted=true，展示“中断正文” | 标记完整最终回答 |
| turn/end completed | 标记轮次结束原因；最后一条正文可标“轮次末正文” | 将 completed 当成结论正确或语义上最终 |
| 无工具的直接回复 | 保留回复，显示“此截面无工具记录” | 生成空的假数据源 |

**重要修正：** 当前实现会将后来才返回的工具从此前回复归属中排除。S1 改为“工具执行身份 + 回复内当时可见投影”分离，保留当时开始事实并隐藏未来结果；这属于待改行为。

回复内工具投影至少携带 `callSeq / resultSeq / cutSeq / resultAvailableAtCut / attributionBasis`。全局工具记录保存完整生命周期；前端不得绕过 cutSeq 展示未来 output。归属不是证据边。

### 3.3 原始历史、压缩与分叉

S1 明确使用 `historyMode: raw-committed`：展示已提交原始历史，不声称是当前有效模型上下文。替换/压缩过的内容可能仍在原始记录中。若无法确定 surface 有效性，标记 unknown；不做自制、不完整的 surface 投影。

分叉记录保留原 session 身份与 fork 来源（接口证据存在时）；继承记录标 inherited，不与分叉后执行重复计数。找不到原来源则保留缺失提示。未来的有效对话视图应复用宿主正式投影能力，不能自己根据“最后一条”删历史。

## 4. 状态模型与关系语义

### 4.1 工具两维状态

- `resultState`: returned / error / missing-start / missing-result。
- `activityState`: running / stopped / unknown。
- running 需要当前运行时明确存在的活跃调用标识，并带 observationTime；仅有 call 没有 result 不是 running 证据。
- turn/end 或会话结束只说明轮次/会话结束；没有工具取消事件时显示“轮次已结束，但工具返回缺失”，不伪造工具 cancelled。
- 当前 schemaVersion 1 的 status 留作旧格式兼容映射；新字段不能靠把 unknown 改名为 running 实现。UI 优先显示两维事实。

### 4.2 关系类型

| 关系 | 依据 | 展示 |
|---|---|---|
| execution-membership | 明确 turn/seq 与 cutSeq | 蓝灰虚线，非证据因果 |
| execution-parent | 工具 PTC parentCallId 等明确字段 | 蓝灰虚线，明确父调用 |
| observed-source | 识别的工具参数/已记录返回 | 蓝实线；请求来源与成功返回分别标记 |
| declared-evidence | 显式 claim/evidence 记录 | 绿色实线，未语义核验 |
| delegation | 已记录的父调用与子会话映射 | 独立委派样式/跳转，不冒充普通工具父级 |
| unresolved | 证据缺失、无权读取、映射缺失 | 黄色占位与原因 |

底层以稳定实体和边建模，不要求每个实体唯一父节点。树上重复出现的证据/工具是 display instance，共享 entityId 与详情；统计按 entityId 去重。循环、深度与节点预算超限时截断并提示，不继续递归。S1 保留现有树布局，复杂 DAG 布局不是阻塞项。

## 5. 子 Agent 设计

### 5.1 先核查映射，再承诺展开

S1 增加专项接口核查：委派工具返回、持久事件或正式会话元数据是否提供 parentSessionId、parentCallId、childSessionId。运行时瞬时父关系若没有持久记录，不能用来重建冷历史。

- 有可靠映射：展示委派节点、子会话状态/读取状态、摘要与“打开子计划”。跳转带 childSessionId 与返回父级入口。
- 无映射：展示原始工具返回，标“子会话映射未记录”；不从自然语言中的字符串猜 ID。
- 无权限/缺失/超限：分别显示 forbidden / not-found / too-large，不静默退回示例。
- 用户展开时才读取子快照；每个子会话独立认证与限额，防止递归读取整个会话树。
- 子 Agent 后来继续工作，不能将返回摘要之后的结果伪装成父回复依据。只有父日志明确记录 consumed child cut/返回版本时才能宣称对应当时截面；否则标“当前子会话快照，非父回复当时已消费内容”。

不支持自动把子 Agent 输出认定为 parent claim 的证据；需要显式引用子输出或来源。

## 6. 显式证据登记（S2，不阻塞 S1 现场联调）

### 6.1 闭环

```text
已记录工具结果 → 列出可引用结果 ID → 登记 evidence/claim
       → 提交一个 claim batch → 绑定指定正文消息 → 结构核验 → 展示
```

不修改旧消息正文，不通过模型事后解释生成运行事实，不要求所有回答都使用 JSON。未登记回答仍正常工作，证据计划显示未绑定。

### 6.2 建议操作契约（设计名，尚非现有 Harness 工具）

1. `pathway_list_results`：返回当前授权会话内、截至本次操作提交边界的已完成工具结果 ID 与脱敏摘要。跨会话/跨轮使用要显式指定，并重新做访问检查。
2. `pathway_register_claims`：提交 `{batchId, evidence[], claims[], target}`；evidence 必须引用已存在 source/result，locator 必须落在已保存结果中。target 优先指定已有 replyId；对未来正文使用同会话/同 turn 的 next-text-message 目标。
3. next-text-message 绑定规则：登记事件之后最早的一条包含 text 的已提交 assistant/message 消费此批次；纯工具请求和 attempt 不消费。批次不得自动跨 turn；中断/结束未出现目标则标 unbound。若目标同时包含工具请求，仍是该正文消息，不等“看起来最终”的回答。
4. 返回结构校验错误，不因登记失败阻塞普通回答；失败批次不创建部分边。重试以 batchId 幂等；同 ID 不同内容拒绝并报 conflict。

工具输出 ID 必须真正进入 Agent 可用结果或 prompt 才能要求引用。若现有工具输出不携带 ID，可先采用 list_results 明确列出，不能假设 Agent 看得见后台元数据。

### 6.3 保存与验证边界

- 不擅用 appendPluginRecord。0.3首版采用正式原生工具调用的正常tool/result JSON文本作为登记载体，由宿主原有会话机制保存；不改旧事件、不新增sidecar。仅exec.agent.session.id当前会话，原生callId=rootCallId；PTC登记明确拒绝。结果受宿主持久化机制管理，不承诺同步落盘checkpoint。
- 仅校验已保存摘录的exact-substring，非文件全文/语义验证；单批输入及完整输出均不超过64kB。Host重放必须配对原生call和sourceEventSeqs，逐字段重算accepted envelope；同批冲突拒绝、重试幂等。后续surface替换导致保存来源变化时保留登记并标source-unavailable，不挂虚假已解析边。跨会话引用暂不支持。
- batch 保存记录关联的 session/reply IDs、cutSeq、注册者类型、注册时间、schema 版本；删除会话时明确独立记录是否保留。
- 验证分开记录：schema-valid、reference-resolved、locator-resolved；semanticSupport 恒为 unverified，除非有额外可审阅核验报告。
- 原文 excerpt 与保存片段不匹配要报定位不通过；脱敏后不能验证的 locator 标 unavailable，不假装通过。
- 导入仍标 imported，不能因 JSON 自称 verified/harness 而升级来源身份。

## 7. 快照与读取接口（S1）

### 7.1 快照元数据

在现有 trace 上增加可选 `snapshot` 与 `capabilities`，旧输入继续可读；破坏原字段含义前必须升 schemaVersion 并提供迁移。

snapshot 最少包括：

- snapshotId、capturedAt、sessionId、hostVersion。
- firstSeq / lastSeq / eventCount / inheritedEventCount（确有宿主数据时填写）。
- historyMode: raw-committed。
- coverage: read-complete / partial / unknown，及 limitations[]。
- bodyPolicy: redacted-preview / metadata-only；截断级别分别为 history、node、field。

read-complete 只表示本次后端所提供的事件范围读取完成，不保证真实世界所有行为都被记录；未取得持久化 checkpoint 时不宣称已落盘或抗崩溃。capturedAt 是读取时间，不是业务数据更新时间。

### 7.2 一致性与开销

保留 await readSession 后统一归一化的单快照路径；不从多个读取瞬间拼一个“完整”历史。若接口不能保证原子截面，标 consistency=unknown，并利用取得的 seq 切口，不能宣称事务快照。

不做后台自动轮询。用户手动刷新时替换整份快照；选择历史回复应按 replyId 尽量保留，若已不存在则显示明确提示。一次只读取所选会话，取消/切会话后不把旧响应渲染到新页面。

既有限额继续保留；拒绝时区分事件数、输入字节、节点数和归一化结果大小。全量读取后的限制不能限制后端峰值，后续优化要使用正式分页读取契约，不偷用同步事件读取。

### 7.3 HTTP 契约增量

- sessions：从已核查的 `sessionQuery.listSessions(signal)` 取得 live/persisted 元数据，分页/过滤由插件显式限额，不返回整个历史。列表不可读的条目显示诊断，不逐项自动加载。
- trace：兼容现有认证 GET；可选 `content=metadata|preview`（S1 新设计），默认 preview 维持受控本地查看，metadata 不含正文。
- 冷历史与在线会话使用同一标识。未知字段忽略或报版本诊断，不因升级偷偷禁用脱敏。
- 内部异常不回传 stack/原始 payload；所有敏感响应 no-store/nosniff。确切 HTTP 错误映射在接口测试中固定，区分 401/403/404/413/读取失败。

## 8. 隐私、保存与导出

### 8.1 采集和浏览

只读宿主已有记录，不额外读取磁盘全文、不重新执行 API、不显示凭证原文。脱敏必须在 Host 向浏览器发送前完成；浏览器显示/导出再次脱敏作为纵深防御，不代替 Host 控制。

metadata 模式采用字段白名单：ID、类型、seq/时间、状态、计数、关系；默认省略 input/output、reply text、claim text、excerpt、snapshot、错误正文、文件绝对路径、URL 查询和自定义自由文本。来源仅显示类型/已脱敏别名。白名单比“删除几个字段”更可靠。

preview 模式允许按限额查看脱敏内容，仍提示启发式脱敏不能识别所有业务敏感信息。已落盘的宿主日志归宿主管理，本插件的“不额外保存”不等于宿主没有原始记录。

S1 不新增持久内容库，不使用 localStorage/IndexedDB 保存 trace 正文；内存视图卸载即释放可达引用（不承诺浏览器物理内存立即擦除）。日志仅记录计数和固定错误码。

### 8.2 两种导出

- 默认“导出结构”：采用 metadata 白名单，无正文和真实资源路径；仍可能包含操作时间等敏感元数据，需提示。
- “导出选中证据包”：明确选择回复/结论路径，显示节点数、来源数、预计内容范围、脱敏与截断提示，确认后保存；用户可取消，不自动回退全量。
- 共享实体按 ID 去重；导出是选择子图的闭包，记录被省略/缺失引用。缺失证据不补造，不把悬空边当完整包。
- trace origin、采集方式和 imported 标识必须保留；不通过导出重新赋予真实宿主身份。

内容哈希如后续加入，只对确定编码的具体快照计算，并注明是否脱敏后；不能冒充原文件全文哈希、真实性证明、签名或防篡改审计。

## 9. 入口与安装策略

S1 保留已实现的独立侧栏页，支持定位 sessionId/replyId。按回复内“查看执行计划”作为目标体验，但必须先核查正式 message action/slot 扩展点：支持则以小适配层接入，不支持则保留独立页，不 monkey-patch 宿主 DOM 或覆盖官方聊天渲染器。

安装前记录当前宿主版本、待启用 bundle、影响 profile 范围、退出/禁用方法；由用户授权后调用正常安装流程。只改必要配置，不复制 Cookie、不私自读 owner 凭证，不开新的 server。安装后验证现有 GUI，按宿主要求刷新/重启；不在无 dev:web watcher 的情况下承诺热更新。

回退：禁用 Pathway bundle并按宿主要求刷新/重启；已有原始会话不应被修改或删除。不要为清除插件临时文件删除整个 profile。

## 10. 分期与实现顺序

### S1：真实执行链路集成（下一开发批次）

1. 核心：增加 cutSeq 工具投影、结果/活性双状态、冲突和顺序依据诊断。
2. Host：快照元数据、完整性/截断来源、live+persisted 列表、metadata 输出白名单。
3. UI：最新正文/中断/轮次结束标签；结构导出默认、所选内容确认；定位到某条回复。
4. 核查并最小实现子会话链接、回复内入口；不可用则明确降级，不影响独立页。
5. 自动化测试通过后，取得用户安装授权，安装本地 bundle并完成真实 GUI 验收。

S1 不等待 S2。若 Host 对 child mapping 或 reply action 不提供可靠扩展点，对应功能标 unavailable，不虚构支持；其余单会话只读闭环仍可验收。

### S2：结论到证据的真实闭环

实现 list_results / register_claims、绑定与持久化、安全复核和引用定位检查；跨轮/子会话证据显式关联。保存方案与权限批准是实施前置，不静默落库。

### S3：后续增强

实时订阅/断线续传、分页/虚拟化、更多文件与 API 适配、有效 surface 视图、数字复算/语义核验。任意 SDK 深度埋点、自动因果证明、可信评分不在当前承诺范围。
