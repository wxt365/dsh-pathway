# DSH Pathway：Agent 执行链路与证据溯源

版本：0.5.0 状态对齐｜日期：2026-10-31｜状态：单会话 MVP 已开发，0.5.0 现场验收待确认

当前交付和未完成项见 [功能与验收清单](<功能与验收清单.md>)。下文保留原设计语义；早期宿主核查事实不是当前宿主的新验收。执行图表示记录归属，不能解释为模型私有思维。0.5.0 在四页签上方统一回复/快照范围，详情与导出遵循回复截面；快照范围下关系图仍展示所选单回复。

## 本轮修订：从日志列表转向回复执行计划

用户反馈：旧版离线页更像日志列表，不能直观表达多源输入怎样逐层汇总成每条回复。主视图改为二维执行计划树，而不是仅增加缩进。

- 每条有正文的 Assistant 消息独立一个计划；默认最新回复，可切换历史回复。工具调用请求本身不是结论回复。
- 根节点为回复，右侧是同轮此前记录的步骤、工具及来源；参照用户提供的 SQL Server 计划截图改为横向布局，结果在左、输入在右，箭头从右向左汇入。PTC 依显式 parentId 展开。
- 视觉以紧凑操作符为主：32px 自绘矢量图标、短标签与实际耗时，164×104 透明节点；只有 hover/选中时显示背景与边框。使用细正交折线与纯白画布，移除大卡片阴影和点阵。顶部统计压缩为单行，画布提供“适应画布”。详细正文、定位与警告仍在详情中保留，不把完整描述挤进节点。
- 两种视角：**执行归属**（虚线，表示记录/先后关系，不证明内容被用于该结论）和 **显式证据**（绿色实线，claim → evidence → 工具/来源）。不能将这两类边混画成同样的因果关系。
- 同轮的中间回复只关联其提交之前的工具；之后执行的工具不能倒挂到它的证据下。多个回复可共享先前执行上下文，但界面必须标记这是记录归属。
- 工具调用之后尚无正文回复的执行留在“待回复执行”；没有 turn/seq 等足够归属信息时进入“未归属”，不猜所属回复。
- 旧 trace 没有 replies 时以“旧版未绑定执行记录”呈现，不伪造真实回复正文。schemaVersion 1 增加可选 replies，旧输入补空数组。
- 画布支持节点选择、分支折叠、全部展开/收起、缩放和局部滚动；详情不再占主图的一半；保留时间线与来源视图。
- 不显示虚构的 SQL 代价百分比、行数、可信分；耗时仅使用已有时间，证据完整性独立提示。
- 升级后的宿主需重新读取当前分发包接口，兼容性结论单列，不沿用旧核查当作新版本已验证。


后续真实环境实施按 [真实集成设计补充](<真实集成设计补充.md>) 执行；该文明确 S1/S2 边界与新增验收，不代表已安装或新增能力已实现。

## 1. 背景与产品定位

Agent 往往只给出结论，用户难以判断是否实际访问过数据、数字来源、计算过程以及证据是否充分。Pathway 借鉴数据库 EXPLAIN ANALYZE 和数据血缘图，把执行过程与证据依赖分开呈现。

**核心定位：让每个重要结论都有可检查的依据，而不是让每个结论看起来都值得相信。**

透明度不等于正确性：真实执行不代表来源可靠，来源可靠不代表计算正确，计算正确也不代表因果推断成立。不生成笼统“可信分”，不展示或声称重建模型私有内部思维。

## 2. 用户与场景

- 分析人员：从结论追查 API 响应、文件片段和计算结果。
- 开发者：定位工具失败、并行调用、缺失结果与不可观测边界。
- 审阅者：区分已记录事实、Agent 声明的引用和未核验假设。

典型流程：选会话 → 浏览执行计划/时间线 → 点击工具 → 查看脱敏请求与响应 → 查看来源定位 → 从结构化结论反查证据。

## 3. 语义边界（强制）

1. **请求访问**：工具参数声明的资源或范围，不证明访问成功。
2. **已返回**：运行事件记录的工具返回内容；可能被截断、摘要化。
3. **已提供给模型**：只有请求上下文记录明确支持时才可标记；MVP 默认未知。
4. **被结论引用**：显式 evidence ID 关系；引用存在不代表证据充分。
5. **已核验**：必须注明核验方法、范围与结果；MVP 仅做结构/引用存在性检查，不自动声明语义或因果核验通过。

事实关系、显式声明关系、事后推断关系必须区分。MVP 不自动猜测证据依赖，不把时间先后当成数据依赖。

## 4. 功能需求

### 4.1 执行视图（P0）

- 从已提交会话事件配对 tool/call 与 tool/result，展示状态、开始时间、可计算耗时、完整性提示。
- 展示步骤/轮次上下文和工具参数、工具返回；缺失开始或返回必须明确标记。
- 计划视图与时间线分离；并行时间区间不人为串行化。
- 不以“模型请求结束”推断“工具/整个任务已完成”。
- 搜索工具名、资源标识、内容；状态筛选；选择节点看详情。

### 4.2 外部 API / 网络来源（P0）

- 明确的网络工具记录 URL、方法/参数（若存在）、工具返回快照、状态码（若记录）、截断情况。
- 保留来源是“工具参数声明”还是“显式采集”的标记。
- 脚本/SDK 内部 HTTP 默认不可观测；不能从脚本中的 URL 推断真实请求。
- 请求头 Authorization、Cookie、API Key、常见 token/密码键及 URL 凭证参数脱敏。
- 工具返回未包含原始 HTTP 响应时，标记“工具返回快照，非原始 HTTP 响应”。

### 4.3 本地文件（P0）

- 显示读取工具声明的文件路径、请求 offset/limit、返回中的行号与片段。
- 请求范围与可解析的返回范围分别展示；无法确认的实际磁盘访问范围标记未知。
- 不重新读取当前文件来冒充历史内容；仅展示当时工具返回。
- 工具返回片段摘要可用于识别快照；不能冒充原文件全文哈希。
- 支持通用 locator 模型：文本行、JSON Pointer、单元格、PDF 页码等；MVP 自动适配文本 read 与 web_fetch，其余通过显式证据输入。

### 4.4 结论溯源（P0）

- 提供结构化 claim/evidence 输入协议，支持证据 ID、来源工具 ID、定位、限制条件。
- 导入的结论标记“显式声明，未语义核验”；缺失证据引用必须报警。
- 选择结论高亮上游证据/工具，不自动添加未声明依赖。
- 原生历史若没有结构化引用，应显示“未记录结论绑定”，不自动生成解释。

### 4.5 回放和导出（P0）

- 提供清楚标识的示例数据，无真实会话时不伪装成实时数据。
- 支持版本化 Pathway trace JSON 导入/脱敏导出。
- 支持离线 HTML 查看器，直接打开本地页面导入数据，无需另起服务器。
- 宿主模式只通过宿主已有认证通道访问记录，不创建无认证旁路。

## 5. 已核实宿主事实

核查对象：本机 DeepSeek Harness 0.2.1-rc.3 分发包，资料来自安装包内 @deepseek-ai 包的 README 与实现。ASAR 非普通目录；已只读提取少量参考文件到被 git 忽略的 .harness-reference。

- dsh-session 提供 session/event 提交事件；同步 snapshotEvents/eventAt/ownEvents 被弃用，新的生产插件不得使用。
- dsh-session 记录 tool/call、tool/result 及模型可见消息；模型流并不等于内部思维全量轨迹。
- dsh-client-ui-trajectory 已有工具输入输出、时间概览与事件账本。因此本项目以“来源 + 内容定位 + 结论证据关系”为增量。
- dsh-client-modules 支持 dsh.client 声明与 ./client 构建产物，由 window.__ModuleLoader__.load 注册工厂。
- 客户端可注册 conversation.view 或根 main/sidebar.panellist 插槽。
- dsh-host-webserver 的普通路由没有全局认证，不能直接用其暴露敏感记录。
- dsh-client-connection 的 /api 通道已有 Host/Origin、身份认证及 owner 检查，应复用 exact Fetch route。
- 外部插件不得调用 appendPluginRecord；自有 claim 数据保存在独立导入/导出格式，不伪造宿主持久化事件。

最终宿主适配接口、读取路径与实测结果另记在 docs/宿主接口与验证.md；未核实能力不在 UI 中标记已支持。

## 6. 架构

```text
Harness 提交事件 / 历史异步读取 / 离线导入
                    ↓
           输入校验 → 脱敏 → 大小限制
                    ↓
       纯函数事件归一化与工具调用配对
                    ↓
   Trace：执行节点 + 来源快照 + 显式证据 + 结论
                    ↓
     计划 / 时间线 / 来源 / 结论 / 详情面板
```

- Host 适配层只订阅事实、提供认证后只读接口；不修改用户文件、不自动调用外部 API。
- 核心为无宿主依赖的 JavaScript ES modules，便于 Node 内置测试与离线回放。
- UI 共用一套浏览器组件，通过薄 React 挂载层进入 Harness；离线版复用同一视图。
- 分发包包含 Host 入口、client bundle、bundle patch、离线 HTML 与文档。
- 不替换当前 GUI、不启动替代服务；安装/启用 profile 前需用户确认并遵守沙箱授权。

## 7. 核心数据模型（schemaVersion = 1）

- Trace：id、title、origin（demo/import/harness）、observability、nodes、sources、evidence、claims、warnings。
- Node：id、kind、toolName、parent/step/turn（若已知）、start/end、status、input、output、sourceIds。
- Source：id、nodeId、kind（file/http/other）、uri、locator、returnedLocator、snapshot、snapshotKind、truncated、observation。
- Evidence：id、sourceId 或 nodeId、locator、excerpt、attribution（explicit/imported）、verification。
- Claim：id、text、evidenceIds、limitations、verification（unverified）。
- 依赖只来自显式结构化声明；执行分组与证据关系不用同一条边混淆。

稳定性：宿主 ID 使用 session ID + toolCallId；重复事件幂等；乱序结果可配对；孤立结果与截断历史给出警告。导入不接受重复 ID、无效类型与超限数据，悬空证据引用可保留但需清晰警告。

## 8. 安全与性能

- 数据默认只在当前宿主/页面内存中，不上传第三方；不注入工具输出 HTML、不执行输入内容。
- 所有 DOM 内容通过 textContent 渲染，外部 URL 仅允许 http/https；不自动加载外部图片。
- 递归脱敏结构化密钥、URL 查询参数及常见文本凭证；启发式脱敏不保证发现任意 PII，导出仍需审阅。
- 入口限制字节数、事件数量、字符串长度和对象深度，避免导入导致内存失控。
- 有限历史或内存保留窗口须展示边界，不把窗口称为整个执行全量。
- 不承诺完全可重现：外部状态、非确定模型输出、写操作均不自动重放。

## 9. MVP 验收标准

1. 需求/设计先于产品实现落盘，README 给出安装、使用和限制。
2. 构建产物可生成，Node 测试通过，核心不依赖模型 API。
3. read 调用展示路径、请求范围、已记录返回行与片段，不能混称原文件全文。
4. web_fetch 调用展示 URL 与记录的工具结果；不臆造 HTTP 状态/请求头。
5. 丢失结果、失败、并行、乱序/重复事件、未知工具均有明确行为。
6. claim 点击能定位显式 evidence；悬空引用报警，无引用不伪造。
7. 导入与导出均脱敏，恶意 HTML 只显示文本，页面不执行它。
8. 离线回放可使用；宿主插件入口和认证接口通过自动测试。真实 profile 安装与 GUI 实测必须单独记录，未安装时不得宣称已上线。

## 10. 分期

- MVP：可验证的工具执行、来源/片段、显式结论引用、离线回放、宿主适配。
- 已追加实现：单会话原生 list_results/register_claims、同会话跨轮显式引用、多文件/共享证据、近期回退与引用闭包、统一范围及紧凑回复视图。安装不等于运行实例已更新，0.5.0 需手动完整重开后验收。
- 待开发：更广泛工具适配、JSON 字段选择、更早回复按需加载、跨子 Agent 会话汇总及消费版本映射。
- 后续：SDK/HTTP 深层埋点、文件全文版本归档、数字复算、反证检查、语义核验与访问权限细化。

## 11. 暂不包含

模型内部思维重建；任意脚本内网络/磁盘活动自动审计；数据库原始响应自动拦截；自动因果证明；全局 profile 静默安装；隐式推测结论依赖；以单一分数担保正确性。
