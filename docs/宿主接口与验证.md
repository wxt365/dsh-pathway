## 研究方式与验证级别

核查本机安装包内提取的 JavaScript 实现与随包 README；缺少的引用从 app.asar 只读解析、以 exclusive-create 提取到忽略目录，未覆盖旧文件。未启动服务、未安装或启用插件、未修改 profile、未改 Harness 实现。下列是**源码核验**，不代表真实 GUI 已安装验证。

## 1. 外部 Host 插件注册

Cordis 支持函数 `(ctx, config)`、类构造器、具有 `apply(ctx, config)` 的对象。模块导出 `name`、`inject`、`apply` 可作为 Host 插件；`inject` 在所需服务全部存在时激活。依据：[Cordis 插件元数据](<../.harness-reference/cordis/src/registry.ts#L91-L132>)、[随包 Host 实例](<../.harness-reference/dsh-tool-fs/lib/index.js#L1185-L1231>)。

外部包通过 `dsh.bundle.patch` 声明一个 patch 文件或文件数组，patch 的 `insert` 添加 Host entry。插入名字允许 package specifier、绝对路径和相对 patch 的文件路径；相对路径转换为 file URL。[profile/bundle 规则](<../.harness-reference/dsh-app-boot/README.md#L48-L65>)、[bundle patch 实现](<../.harness-reference/dsh-app-boot/lib/index.js#L511-L530>)。

可运行的最小文件布局（仅示例，此研究未安装）：

```json
{
  "name": "dsh-example-history", "version": "0.0.1", "type": "module",
  "exports": "./host.js",
  "engines": { "dsh": "0.2.1-rc.3" },
  "dsh": { "bundle": { "patch": "cordis.patch.yml" } }
}
```

```yaml
- insert:
    - id: example-history
      name: ./host.js
```

```js
export const name = 'example-history';
export const inject = ['connection', 'sessionQuery'];
export function apply(ctx) {
  ctx.connection.fetch.register({
    path: '/api/example-history', methods: ['GET'], requestBody: 'buffered',
    async fetch(request) {
      const id = new URL(request.url).searchParams.get('sessionId');
      if (!id) return new Response('sessionId required', { status: 400 });
      const snapshot = await ctx.sessionQuery.readSession(id);
      return Response.json({ session: snapshot.session.id, count: snapshot.events.length }, {
        headers: { 'cache-control': 'no-store', 'x-content-type-options': 'nosniff' },
      });
    },
  });
}
```

这个示例只返回计数，不暴露事件内容；真实功能的脱敏、限额、错误安全封装在 [Host 实现](<../src/host.js>)。是否启用外部包仍需正常安装/选择 bundle 或用户授权 profile patch；放进工作区不会自动激活。Host 代码在宿主进程执行，不受工作区工具沙箱隔离：[插件管理安全说明](<../.harness-reference/dsh-plugin-manager/README.md#L28-L40>)。

## 2. session/event 的实际签名

```js
ctx.on('session/event', (session, event) => {
  // session.id, event.type, event.seq, event.time, event.data
});
```

实际 publication 的参数是 `[this, event]`，carrier 是内部 dispatch 的 this/filter 输入，**不是**第三个 listener 参数。[提交实现](<../.harness-reference/dsh-session/lib/index.js#L1579-L1596>)。事件 envelope 是 `{type, seq, time, data, surfaceOp?, sourceEventSeqs?}`，`time` 是 `Date.now()` 毫秒时间戳，seq 零起连续：[构造实现](<../.harness-reference/dsh-session/lib/index.js#L1517-L1537>)。

通知在 append 时同步执行，不等待异步 listener；抛出或返回 Promise rejection 按 listener 隔离并告警，不回滚已提交事件：[observer containment](<../.harness-reference/dsh-session/lib/index.js#L1226-L1239>)。不能在 listener 中重入 append：[publication guard](<../.harness-reference/dsh-session/lib/index.js#L1563-L1571>)。`ctx.on` 的 listener 随拥有 fiber 清理：[事件生命周期](<../.harness-reference/cordis/src/events.ts#L89-L106>)。新挂 listener 不会重放已有历史；seed 事件也不触发该 feed：[seed 契约](<../.harness-reference/dsh-session/lib/index.js#L1349>)。

## 3. 历史异步读取

```js
const { session, inheritedEventCount, events } =
  await ctx.sessionQuery.readSession(sessionId);
```

这返回 header 和完整 raw log，而不是 Session 对象。读取 live 优先，其次持久化；冷读取不把会话加入 live store，readSession 通过 `Session.create` 重放校验：[readSession 实现](<../.harness-reference/dsh-session-query/lib/index.js#L1075-L1088>)、[source resolution](<../.harness-reference/dsh-session-query/lib/index.js#L128-L156>)。冷路径 open read handle → read → close，不写存储；崩溃未闭合尾部可能追加内存合成的 interrupted closers：[冷读实现](<../.harness-reference/dsh-session-query/lib/index.js#L21-L54>)。

`listSessions(signal)` 异步列出 live+persisted，返回 cloned records；`ctx.sessions.list()` 则仅在线会话。[统一查询 list](<../.harness-reference/dsh-session-query/lib/index.js#L95-L118>)。本项目列表只读 live metadata，明确 `scope: 'live-only'`；按已知 id 的 trace 接口仍能读取冷历史。

`observeSession(id,{signal,projectionMode:'none'|'all'})` 是另一个异步、lease-based 接口，适合反复观察；不能拿 lease 当裸 events 数组，消费者须管理 disposal：[observation reader](<../.harness-reference/dsh-session-query/lib/index.js#L343-L395>)、[缓存/lease 规则](<../.harness-reference/dsh-session-query/README.md#L108-L114>)。

限制：必须已有具体 sessionQuery backend；抽象 query 包不单独 mount。[backend 约束](<../.harness-reference/dsh-session-query/README.md#L26-L43>)。readSession 全量读，非分页；其签名没有 signal 参数。`snapshotEvents`、`eventAt`、`ownEvents` 同步 reader 已弃用，禁止新生产调用：[同步 reader policy](<../.harness-reference/dsh-session/README.md#L60-L64>)。query 没有 caller/session 级授权，读取方必须自行收窄：[query 限制](<../.harness-reference/dsh-session-query/README.md#L147-L152>)。

## 4. 工具事件：不要猜字段

标准工具开始：

```js
{
  type: 'tool/call', seq: 10, time: 123,
  data: { turn: 0, step: 0, callId: 'call-1', name: 'read', arguments: { file_path: 'a.txt' } }
}
```

标准工具结果：

```js
{
  type: 'tool/result', seq: 11, time: 456,
  surfaceOp: 'append', sourceEventSeqs: [10],
  data: {
    turn: 0, step: 0,
    message: {
      id: 'message-uuid', role: 'tool',
      source: { kind: 'tool', callId: 'call-1' }, toolCallId: 'call-1',
      content: [{ type: 'text', text: 'recorded output' }], isError: false
    },
    // error?: {name,code,...} ; meta?: tool-provided metadata
  }
}
```

来源：[call/result writer](<../.harness-reference/dsh-agent-loop/lib/index.js#L680-L706>)、[tool result message](<../.harness-reference/dsh-llm/lib/types/message.js#L88-L99>)。结果身份在 `data.message.toolCallId` 和 `data.message.source.callId`，不在 `data.callId`；返回内容在 `data.message.content`，不是 `data.result`。

Assistant message 的 `data.message.content` 也记录 `{type:'tool-call',id,name,arguments}`，但它表示模型请求而非开始事实；`tool/call` 才是执行开始记录。[assistant settle/dispatch](<../.harness-reference/dsh-agent-loop/lib/index.js#L1148-L1167>)。结果可能是 crash/fork 恢复产生的合成错误；没有 call 不等于历史完全没有模型请求：[recovery 实现](<../.harness-reference/dsh-session/lib/types/repair.js#L104-L173>)。

`run_code` 子调用另记：

- `tool/ptc-dispatch-start`: `{rootCallId,parentCallId,subCallId,name,arguments}`。
- `tool/ptc-dispatch`: `{rootCallId,parentCallId,subCallId,name,arguments,isError,error?,content,meta?}`。

[PTC writer](<../.harness-reference/dsh-tools/lib/index.js#L1400-L1429>)。只配标准 tool/call 与 tool/result 不会自动包含这些子工具；未知工具或脚本内部网络/文件访问不能据此声称全量观测。

## 5. 同源 endpoint / 页面与安全

**可以**复用现有 Host，不应创建第二服务。

推荐：`ctx.connection.fetch.register({path:'/api/pathway/...',methods:['GET'],requestBody:'buffered',fetch(request){...}})`。这是 exact path registry，接收 WHATWG Request、返回 Response；注册自动绑定 caller fiber，重复 path 拒绝。[route registry](<../.harness-reference/dsh-client-connection/lib/index.js#L820-L854>)。路径必须在 `/api/` 下，路径段限定字母数字、`_ $ . -`，无空段或 `.` / `..`：[path 校验](<../.harness-reference/dsh-client-connection/lib/index.js#L926-L930>)、[route 校验](<../.harness-reference/dsh-client-connection/lib/index.js#L973-L976>)。

现有 `/api` carrier 先执行 `admit` 的 Host/Origin fence + cookie/Peer 身份认证，exact Fetch route 又拒绝非 owner principal：[carrier](<../.harness-reference/dsh-client-connection/lib/index.js#L1044-L1058>)、[admission](<../.harness-reference/dsh-client-connection/lib/index.js#L736-L750>)、[owner check](<../.harness-reference/dsh-client-connection/lib/index.js#L826-L831>)。同一个 exact Fetch route 也能返回 `text/html` 页面与 JS Response，无需 client bundle，但它不是 Harness UI slot 自动注册。浏览器先通过既有根 URL 完成登录后，同源 fetch 会带 cookie；此处不新建 token 交换。[认证契约](<../.harness-reference/dsh-client-connection/README.md#L38-L53>)。

备选：`ctx.webServer.register({kind:'exact',path,handler(req,res)})`，Node HTTP handler 自己拥有 response；必须用 `ctx.effect(() => register(...))` 管生命周期。可以先调用 `ctx.connection.requestRejection(req)` 获得 `undefined | 401 | 403` 再服务数据，但此条原始路由不会自动拥有 shared Fetch route 的 owner-principal 检查或 `connection/request` waterfall。[web route 实现](<../.harness-reference/dsh-host-webserver/lib/index.js#L320-L333>)、[HTTP dispatch](<../.harness-reference/dsh-host-webserver/lib/index.js#L377-L405>)、[requestRejection](<../.harness-reference/dsh-client-connection/lib/index.js#L736-L750>)。

**不能**以“同源/loopback”代替鉴权：webServer 不提供全局认证或 origin policy；普通 route 不会继承 `/api` 的防护。[明确限制](<../.harness-reference/dsh-host-webserver/README.md#L127-L131>)。同源 HTML/脚本有访问整个已认证 owner 界面的能力，故只服务受信固定代码，不能把历史工具输出当 HTML 执行，不能引入不可信脚本。

## 6. 本项目接口与测试边界

- `GET /api/pathway/sessions` → `{sessions:[{id,title,createdAt,live:true}],scope:'live-only'}`。
- `GET /api/pathway/trace?sessionId=...` → 已脱敏归一化 Trace。
- 不注册事件订阅、不保留缓存、不写 Session，不读同步历史，不创建服务。
- 全量历史超过 20,000 events 或序列化 8 MiB 返回 413，不静默裁剪。**限额发生在 readSession 完成之后，不能限制 query 后端本身的全量读取峰值。**
- 读取错误只返回固定错误码，不返回内部 stack/message；Response 使用 no-store/nosniff。

[自动化测试](<../test/host.test.js>) 使用 mock context 和真实 Request/Response，验证路由契约、异步冷读、脱敏、错误、输入限制和超限拒绝。2026-10-31 执行 `node --test test/host.test.js`：8 tests / 8 pass / 0 fail。它们**不证明**真实 Cordis 装载、浏览器 Cookie/origin 策略或 GUI 已通过联调；这些行为的当前证据是上列宿主源码。
