# DSH Pathway

DeepSeek Harness **执行链路与证据溯源**插件。像查看数据库执行计划一样检查工具调用、文件/API 来源和显式结论证据。

> 可追溯 ≠ 结论正确。插件展示已记录事实和显式引用，不重建模型私有思维，不把访问过的数据自动认定为结论依据。

- [证据协议](<docs/证据协议.md>)：如何为真实记录添加结构化结论与证据。

## S1：真实集成开发版

- 回复以 cutSeq 固定提交截面，保留当时已开始但未返回的调用；图、详情和搜索不读取未来结果。
- 手动快照显示时间、seq 范围与覆盖边界；原始历史不等于当前模型上下文。
- 默认“导出结构”使用字段白名单；“导出选中内容”只保存所选回复/结论子图，需确认。
- 导出为兼容 schemaVersion 1 的独立裁剪记录，保留范围说明；不把裁剪包当完整宿主历史。

代码已实现，并已获授权安装到 desktop profile；用户确认入口、真实会话加载和整页滚动可用。详细数据正确性与新增交互继续现场验收；S2 证据登记工具未实施。

现场交互修订：0.2.1补宿主容器上下滚动，0.2.2增加空白画布鼠标拖拽，0.2.3将计划节点详情改为右侧独立滚动抽屉（关闭按钮/Esc与焦点返回），避免滚动到图底部。

## 0.2：按回复查看的执行计划树

主视图不再是日志列表，而是类似查询计划的二维树：**回复在左，步骤/工具居中，来源在右，箭头从右向左汇入结果**。每条有正文的 Assistant 消息独立一个计划，默认最新回复；支持分支折叠、全部展开/收起、缩放、画布局部滚动与节点详情。

- **执行归属**：虚线显示同轮、该回复提交之前已记录的执行，不表示这些内容都被模型使用。
- **显式证据**：绿色实线显示回复 → 结论 → 证据 → 工具/来源的反向溯源；缺少绑定明确提示，不根据时间顺序猜测。
- **待回复 / 未归属**：回复之后的调用或缺失轮次的执行单独保留，不倒挂到此前回复。
- **旧数据兼容**：无 replies 的旧 trace 显示“旧版未绑定执行记录”，不伪造正文。

[新版兼容性核查](<docs/新版宿主兼容性.md>) 确认本机已升级至 **0.2.1-rc.5**；插件引擎声明已同步更新。真实 profile 安装仍未执行。

## 已实现的 MVP

- **执行计划树**：按回复组织 tool/call 与 tool/result；支持 PTC/run_code 子工具、父级定位、失败和缺失结果提示。
- **时间线**：根据记录时间展示并行区间；缺失结果不伪造结束时间。
- **来源快照**：read 的文件路径、请求范围、记录中的返回行和片段；web_fetch 的 URL 与工具返回。
- **结论与证据**：显式证据引用、反向定位、高亮来源和工具；缺失引用警告，全部声明未语义核验。
- **安全回放**：导入/导出前脱敏、8 MiB 限额、文本安全渲染；自包含离线查看器。
- **宿主适配**：复用 /api 的认证 exact Fetch 路由，无额外服务、不修改 Session、不自动访问原始文件/API。

## 本地运行（无需模型 API）

```bash
npm install
npm run build
npm test
```

直接用浏览器打开 [离线查看器](<dist/pathway.html>)，默认显示明确标识的合成示例；也可以导入 [示例 trace](<examples/demo.trace.json>)。页面无需启动服务器，不会发出示例 API 请求。构建产物被 Git 忽略，首次使用先 build。

将已经导出的 Harness 事件转换为 Pathway trace：

```bash
node scripts/export-session.mjs /absolute/path/events.json ./new-trace.json my-session
```

输入可以是事件数组、带 events 字段的 JSON 或逐行 JSON；投影已记录的工具事件与有正文的 Assistant 消息，并按 turn/提交顺序建立回复执行归属。输出必须是尚不存在的新文件，不覆盖原始资料。不同历史格式需要先使用宿主支持的迁移/导出流程。不要直接发布含凭证的原始会话日志。

## 安装到 Harness

当前核查基线：**0.2.1-rc.5**。0.2 包精确声明该版本；不同宿主版本需重新核查和调整准入声明。

1. 在本工作区执行 `npm install && npm run build`。
2. 在当前 Harness 的“插件”页，通过本地包安装方式选择此工作区的绝对路径（或相应的 `file:`/`link:` 安装 spec），启用 `dsh-pathway` bundle。
3. Host 部分需要 `connection`、`sessionQuery`，客户端需要 layout/sidebar/slots；缺依赖时 Cordis 等待而非自行启服务。
4. 按宿主提示应用或重启，刷新现有 GUI；侧栏会出现“执行链路”。**放进工作区并不等于已安装。**
5. 选择在线或持久化历史会话，点击“刷新会话”手动更新记录。MVP 不订阅实时增量。

安装会修改 profile 并让插件代码在宿主进程中运行，影响该 profile 的所有会话，需明确授权。开发过程未代替用户改全局 profile、未启动替代 GUI，也没有承诺无需刷新自动更新。

HTTP 接口只供现有已认证 owner 通道使用：

```text
GET /api/pathway/sessions
GET /api/pathway/trace?sessionId=<id>
```

会话下拉框使用官方 sessionQuery 列出在线与持久化历史（最多1000项）；trace 接口按 ID 异步读取历史。`content=metadata` 返回白名单结构，默认 `preview` 返回脱敏片段。不增加新的鉴权 token 或未认证旁路。Electron file:// carrier 尚未联调；本版客户端针对 HTTP Web GUI。

## 测试与构建

```bash
npm test                  # 核心、脱敏、Host 路由单元测试
npm run test:integration  # build + 真实 Cordis 生命周期测试（需要本机提取的随包参考）
npm run test:browser      # build + Chrome 真实浏览器离线交互测试
```

浏览器测试默认使用 macOS Google Chrome；其他平台先安装 Chrome/Chromium，再设置 `PATHWAY_CHROME=/absolute/path/to/chrome`。浏览器测试覆盖四个视图、筛选、证据跳转、导入脱敏、HTML 注入防护和移动端横向溢出。截图生成在 artifacts 目录。

真实 Cordis 测试仅在被忽略的本机参考目录存在时执行，否则明确 skip；真实使用的是 Cordis 注入/卸载机制，slots/React 为 fixture，并不等于整个 GUI 联调。具体结果见 [验证记录](<docs/验证记录.md>)。

## 当前限制（重要）

- **没有安装到当前真实 profile，尚未完成该 GUI 的认证后端到端联调。** 当前证据为源码核查、单元测试、真实 Cordis 生命周期及离线 Chrome 测试。
- 宿主数据是手动刷新快照，不是实时流。未闭合调用标为“返回缺失、活性未知”，不根据缺少结果断言仍在运行。
- 不跨子 Agent 会话自动汇总；仅在持久 header 明确记录父子关系时提供会话跳转，不证明父调用对应关系或当时消费内容。单会话 PTC 子调用可以展示。
- 正式 `conversation.chat.assistant-actions` 扩展点已找到，但只在 turn-tail 提供轮次末消息动作，不覆盖每条中间正文；本轮未注册回复内按钮，继续使用独立页。支持 mount 参数 sessionId/replyId 及 URL 参数 pathwaySession/pathwayReply 定位，参数不会替你切换宿主路由。
- 脚本/SDK 内部的文件访问与 HTTP 请求不可见；不拦截任意流量。
- 只自动适配 read 与 web_fetch/http_request；其他工具仍显示输入输出。没有记录的 HTTP 状态码、原始响应、文件版本不会臆造。
- 文件快照是当时工具返回片段，**不是原文件全文版本**；返回内容是否进入后续模型上下文默认未知。
- 真实历史没有结构化 claim/evidence 时，结论视图为空，必须显式补充引用；不自动“解释”模型结论。
- 脱敏是启发式，不能保证发现所有 PII 或自定义凭证，分享前仍需人工审阅。
- 事件最多 20,000 条、执行节点最多 5,000 个、JSON 8 MiB、单字符串 100,000 字符；字符串截断会标记。界面尚未虚拟化，不适合超大历史；计划分支显示上限为 1500 个工具投影节点 / 40 层，超出显示提示。
- Host 限额发生在历史全量读取之后，不能限制宿主后端的读取峰值。超限拒绝而非假装显示全量。
